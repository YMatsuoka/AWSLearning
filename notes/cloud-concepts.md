# クラウドの概念と定義（Azure対比メモ） ☁️

AWSクラウドプラクティショナー試験で問われる「クラウドの基本」を、Azureの知識をベースに整理したよ！

## 1. クラウドコンピューティングの5つの特性（NISTによる定義）
AWSでも試験にめっちゃ出る「クラウドのノリ」だよ。

| 特性 | 要はこれ！ | Azureでの呼び方 |
| :--- | :--- | :--- |
| **オンデマンド・セルフサービス** | 欲しい時に自分でポチればすぐ使える。 | 同じ |
| **幅広いネットワークアクセス** | ネットがあればどこからでもアクセスできる。 | 同じ |
| **リソースのプーリング** | 巨大なリソース（マルチテナント）をみんなで分け合う。 | 同じ |
| **迅速な弾力性（エラスティシティ）** | 必要に応じてすぐ増やせるし、減らせる。 | **スケーラビリティ / 弾力性** |
| **計測されるサービス** | 使った分だけお支払い（従量課金）。 | **従量課金制 (Pay-as-you-go)** |

## 2. 3つのサービスモデル
「どこまでAWSがやってくれるか」の境界線。

- **IaaS (Infrastructure as a Service)**: 
  - AWS: **EC2**, VPC, EBS
  - Azure: Virtual Machines, VNet
  - 自由度MAX。OSから自分で管理。
- **PaaS (Platform as a Service)**: 
  - AWS: **Elastic Beanstalk**, Lambda, RDS
  - Azure: App Service, Azure Functions, SQL Database
  - コードを書くだけ。サーバー管理はお任せ。
- **SaaS (Software as a Service)**: 
  - AWS: **Amazon WorkDocs**, Chime
  - Azure: Microsoft 365, Dynamics 365
  - 完成したソフトを使うだけ。

## 3. 3つのデプロイモデル
「どこにインフラを置くか」の話。

- **パブリッククラウド**: 
  - AWSやAzureそのもの。ネット経由で誰でも利用可能。
- **プライベートクラウド (オンプレミス)**: 
  - 自社専用のデータセンター。
  - AWS: **AWS Outposts** を使うと、自社DCにAWSの機材を置ける（Azure Stack的なやつ）。
- **ハイブリッドクラウド**: 
  - パブリックとプライベートを混ぜて使う。Direct ConnectとかVPNで繋ぐのが一般的。

## 4. クラウドの6つのメリット（試験頻出！）
「オンプレミスと比較して何がいいの？」というポイント。

1. **固定費（CapEx）を変動費（OpEx）に変えられる**: 最初にデカい金がいらない。
2. **スケールによる経済のメリット**: AWSが巨大だから、ユーザーは安く使える。
3. **キャパシティを推測する必要がなくなる**: 足りなくなったら増やせばいいだけ。
4. **スピードと俊敏性の向上**: 数分で世界中に展開できる。
5. **データセンターの運用保守に金を使わなくて済む**: AWSにお任せして、自分たちはアプリ開発に集中！
6. **数分でグローバルに展開**: 世界中のリージョンに一瞬でデプロイ。
